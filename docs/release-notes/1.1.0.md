WSF 1.1.0 plays WarioWare: Smooth Moves in archive mode, and the game's European and Japanese releases in game mode. It also fixes the lengths of sounds in which a track polls a variable or waits for ever, and skips the sequences that make no sound.

WSF rips Nintendo Wii sequenced music into a PSF-family format and plays it with the game's AX microcode on an emulated GameCube/Wii DSP. The release comes with a ripper (`wsfrip`), a renderer (`wsfplay`) and a foobar2000 component. `docs/wsf.md` describes the format.

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. For other systems, the README explains how to build from source.

## New in 1.1.0

- **WarioWare: Smooth Moves in archive mode.** The game links a 2006 version of the sound library and an older AX microcode. Archive mode couldn't play it. Only the USA release could be ripped, in game mode. The model now follows that version. Archive mode plays the game's sequences as the game does. A loose sound archive with the game's `main.dol` is ripped in archive mode too. The length analysis for this game now runs with the DSP in both modes. Its sounds end where they fall silent.
- **Game mode for other releases.** A release or revision of a game with a driver profile now gets game mode when its code matches. `wsfrip` finds the profile's functions in the release's `main.dol` by their code. The European and Japanese releases of WarioWare: Smooth Moves rip in game mode this way.
- **Messages.** When archive mode can't play a game, `wsfrip` now says whether game mode can rip it, or another release of it.

## Fixed in 1.1.0

- **Lengths of sounds in which a track polls a variable.** In some sounds, a track checks a variable once a tick until the game sets it. In others, a track counts in a variable once a tick. `wsfrip` counted each pass of such a track as a loop of the sound. Music could then get a length of a few ticks and the fade. A sound effect could also end at its first rest, or loop where it should end. A pass that changes nothing in the sound no longer counts as a loop. The loops then come from the track that plays. A held note can now also loop while another track polls. Loops that go round before a sound is first heard no longer count either. Rips made with 1.0.0 keep their tags. Rip a game again to get the new lengths.
- **Sounds that ran for ten minutes.** Some ambiences and engine sounds hold a note on a looping wave on one track while another track loops. The first track never continues. It still kept the other track's loops from counting. Such a sound now gets two loops of the looping track and the fade. In other sounds, a later track holds a note that never ends and only changes its volume or pitch, over and over, while the other tracks wait. Such a sound now loops on that track.
- **Loops that contain a count.** In some sounds, a later track plays a note and then counts ticks in an inner loop before the track repeats. Each repeat of the inner loop cleared the length analysis's record of that note. The track's loops then didn't count. Such a sound could run to the ten-minute limit. The notes of a loop now include those of the loops inside it.
- **The silence after a sound.** A sound that ends gets half a second of silence after its last sound. Some sounds got 3 ms less. Their half second began with the last 3 ms frame of sound, rather than after it.
- **Silent sequences.** Placeholders, muted sounds and sequences that only set values for the game were ripped as half a second of silence. `wsfrip` now lists and skips the sequences that make no sound: those whose volume in the archive is 0, and those that the length analysis finds never sound.
- **Numbers in tags.** The `length`, `fade` and `volume` tags read the same under every locale. A host program could set a locale that writes decimals with a comma. Every rip then played at the default length, and a volume of 0.5 read as 0. The `volume` tag now also takes a comma before decimals. The `length` and `fade` tags already did.
- **Long WAV files.** `wsfplay` refuses a length that a WAV file can't hold, a little over 9 hours, before it renders anything. It used to refuse only after rendering. FLAC files have no such limit.
- **Rips that share a folder.** When several inputs rip into one folder, `wsfrip` gives the later rips' files other names. A later rip used to replace an earlier rip's files of the same names. That happened with `-o` and two releases of one game, or two games whose sound archives have the same name. On Windows and macOS it also happened to two inputs whose names differ only in case, such as `Game.rvz` and `game.iso`.
- **A mistyped `--microcode` path.** When `wsfrip` couldn't read the file given with `--microcode`, it said that the file held no AX microcode. It now says that it can't read the file.

## Features

- **Ripping.** `wsfrip` rips a Wii disc image (ISO, NKit, RVZ, WIA, GCZ, WBFS, CISO or WDF), an extracted disc, or a sound archive (`.brsar`, with a game's `main.dol` for AX's microcode). It creates a `.wsflib` and a `.miniwsf` for each sequence. The game partition must be stored decrypted. NKit, RVZ and WIA images store it that way. Dolphin converts other images to RVZ without losing data. `wsfrip` plays each sound to determine its length and fade tags. `--bgm` rips only the music. Drag and drop also works.
- **Two rip modes.** Game mode runs the game's sound code on an emulated Wii. The rips play as the game does. Game mode requires a driver profile for the game. Wii Sports, Wii Play, WarioWare: Smooth Moves, Mario Kart Wii, Wii Music and Animal Crossing: City Folk (all USA) have one. Another release whose code matches gets a profile derived from it. Archive mode plays a sound archive from any game with WSF's model of the SDK's sound player. The model follows the 2006, 2007 and 2008 versions of the sound library.
- **The game's mixing.** In both modes, the game's AX microcode runs on an emulated DSP. The mixing, filtering and resampling therefore match the console.
- **Rendering.** `wsfplay` renders rips to WAV or FLAC at the Wii's rate of 32,000 Hz.
- **foobar2000.** The component plays `.miniwsf` files with their length and fade tags. It supports tag editing, ReplayGain and endless playback. The component renders ahead of playback on a separate thread and saves the emulation's state as it goes. Seeking back is instant. Seeking forward only waits for rendering to reach the target.

## Known limitations

- Archive mode's model follows the versions of the sound library in WarioWare: Smooth Moves (2006), Wii Sports (2007), Mario Kart Wii (March 2008) and Wii Music (June 2008). A game with another version may play differently from the console. The newest version can put biquad filters on a track's notes. Archive mode applies the library's preset filters. It doesn't apply a filter that a game defines in its code. Some games' AX microcode is a version that the model can't drive. Those games can only be ripped in game mode. Game mode requires a profile for the game.
- Game mode for another release of Mario Kart Wii, Wii Music or Animal Crossing: City Folk requires a profile made for it. Their version of the sound library checks a flag. The flag's address can't be found the way the functions are.
- Sounds that play until the game stops them, such as ambiences, get two loops and a fade when the ripper can find their loops. Otherwise they play until their notes end, for at most ten minutes.
- Only sequences are ripped. Use tools such as vgmstream for BRSTM streams. Wave sounds, and sequences whose data the game can't load, are skipped.
- The output is the TV's stereo mix. The Wii Remote speaker's sounds and surround aren't played.
- Effects that a game runs on its auxiliary buses, such as reverb, aren't played. The rips have the dry mix.
- Encrypted disc images aren't read.

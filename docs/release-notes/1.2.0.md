WSF 1.2.0 rips WiiWare games, and The Legend of Zelda: Twilight Princess in game mode. Archive-mode libraries now hold only the data that their sequences play. A large sound archive's rips therefore play in foobar2000.

WSF rips Nintendo Wii sequenced music into a PSF-family format and plays it with the game's DSP program on an emulated GameCube/Wii DSP. The release comes with a ripper (`wsfrip`), a renderer (`wsfplay`) and a foobar2000 component. `docs/wsf.md` describes the format.

## Downloads

| File | Contents |
|---|---|
| `wsf-1.2.0-win-x64.zip` | `wsfrip` and `wsfplay` for 64-bit Windows |
| `foo_input_wsf-1.2.0.fb2k-component` | the foobar2000 component, for 64-bit and 32-bit foobar2000 v2 |

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. For macOS, the README explains how to build from source.

## New in 1.2.0

- **WiiWare games.** `wsfrip` rips a WiiWare game, or another title for the Wii's NAND, in archive mode. The input is a folder with the title's TMD and its decrypted contents. A WAD unpacker that decrypts the contents writes such a folder. A Wii's NAND keeps each installed title in one. So does Dolphin's NAND after Tools › Install WAD. A WAD holds the contents encrypted. `wsfrip` rejects it and says how to get the folder. The ripper decompresses the main program and the sound archives that a title stores compressed. Game mode doesn't rip titles. A title's game reads its files from the NAND, and game mode emulates a disc.
- **The Legend of Zelda: Twilight Princess in game mode.** Game mode now plays games whose sound library is JAudio2, from Nintendo's JSystem. The first is Twilight Princess (USA, revision 2). `wsfrip` finds the game's sound files by their headers. It rips each piece of music with the wave groups that the piece plays. `--list` lists the game's sounds and sections. Rips of this game require a player newer than 1.1.0. WSF 1.1.0 refuses them. They take more processing to play than other games' rips. A slow computer may not play them in real time.

## Fixed in 1.2.0

- **Large sound archives in foobar2000.** An archive-mode library held the game's whole sound archive. The foobar2000 component refused every file over 256 MB. The rips of a large archive therefore didn't play in foobar2000. An archive-mode library now keeps only the data that its sequences play. The rest of the archive's data becomes zeros. A large archive's library therefore shrinks to a fraction of its size. Its rips sound the same. The component now reads files up to 1 GiB. Rips made with 1.1.0 keep their libraries. Rip a game again into an empty folder to get the smaller library. Game mode still puts the whole archive in its library.
- **The archive-mode notice.** The notice told the user to rip the game itself, even when the input already was the game. With `--mode archive` on a game that has a driver profile, the notice now says to leave out `--mode archive`. On a game without a profile, it leaves the advice out.
- **Discs with nothing to rip.** A disc with neither a sound archive of NW4R SND nor JAudio2's start-up archive got the archive-mode notice and "0 miniwsf files", and `wsfrip` exited with 0. `wsfrip` now stops with an error and exits with 1.
- **A sound archive's `main.dol`.** A loose `.brsar` takes the build of the sound library from the `main.dol` given with it, as well as AX's microcode. The help and the README asked only for a game's `main.dol`. Another game's `main.dol` can change how the archive plays. They now ask for the `main.dol` of the game that the archive comes from.
- **Low-pass filters and loud notes in later games.** Archive mode played every version of the sound library from June 2008 on as Wii Music's version. Versions from November 2008 on take a low-pass filter's cutoff from a table. Archive mode computed it with the older formula. Most cutoffs came out up to about a third of an octave too high. The lowest came out up to 1.4 octaves too low. Versions from September 2009 on let a note's volume rise to twice full level. Archive mode held it to full level. A volume LFO on a loud note, for example, lost the upper half of its swing. Rips made with earlier versions of WSF play the new way too. The rip records the version of the sound library.
- **A second rip into the same folder.** A rip in the other mode replaced the library of the rips already in the folder. Those rips then failed to play. A library now gets the next free name, such as `<name>_2.wsflib`, when the folder holds a library of that name with other contents. The rips already in the folder therefore still play.
- **File names outside ASCII.** A rip's file names now keep letters and other printable characters outside ASCII, such as accented letters. Each byte of such a character used to become an underscore. Spaces, punctuation and control characters still become underscores.
- **Text outside ASCII on discs.** `wsfrip` now decodes a Japanese disc's title as Shift-JIS, and the title of any other disc as Windows-1252. `wsfrip` also decodes the names in a disc's file system as Shift-JIS. The text then appears as it should in `wsfrip`'s line for the disc, in the default `game` tag and in a library's file name. Each byte outside ASCII and half-width katakana used to come out as `%XX`.
- **Damaged files.** A sequence whose variable-length argument ran past the end of its data made WSF hang. Such a sequence now stops there. A damaged rip file whose program data stops exactly at a multiple of 1 MiB now gives the message "truncated program data". It used to give "corrupt program data".

## Features

- **Ripping.** `wsfrip` rips a Wii disc image (ISO, NKit, RVZ, WIA, GCZ, WBFS, CISO or WDF), an extracted disc, an unpacked WiiWare title, or a sound archive (`.brsar`, with the `main.dol` of its game). It creates a `.wsflib` and a `.miniwsf` for each sequence. The game partition must be stored decrypted. NKit, RVZ and WIA images store it that way. Dolphin converts other images to RVZ without losing data. `wsfrip` plays each sound to determine its length and fade tags. `--bgm` rips only the music. Drag and drop also works.
- **Two rip modes.** Game mode runs the game's sound code on an emulated Wii. The rips play as the game does. Game mode requires a driver profile for the game. Wii Sports, Wii Play, WarioWare: Smooth Moves, Mario Kart Wii, Wii Music and Animal Crossing: City Folk (all USA) have one. So does The Legend of Zelda: Twilight Princess (USA, revision 2). Its sound library is JAudio2. Another release whose code matches gets a profile derived from it. Archive mode plays a sound archive from any game with WSF's model of the SDK's sound player. The model follows the 2006, 2007 and 2008 versions of the sound library.
- **The game's mixing.** In both modes, the game's DSP program runs on an emulated DSP: AX's microcode, or JAudio2's. The mixing, filtering and resampling therefore match the console.
- **Rendering.** `wsfplay` renders rips to WAV or FLAC at the Wii's rate of 32,000 Hz.
- **foobar2000.** The component plays `.miniwsf` files with their length and fade tags. It supports tag editing, ReplayGain and endless playback. The component renders ahead of playback on a separate thread and saves the emulation's state as it goes. Seeking back is instant. Seeking forward only waits for rendering to reach the target.

## Known limitations

- Archive mode's model follows the versions of the sound library in WarioWare: Smooth Moves (2006), Wii Sports (2007), Mario Kart Wii (March 2008) and Wii Music (June 2008). The model also follows two changes in versions from November 2008 and September 2009. `docs/wsf.md` lists them. A game with another version may play differently from the console. Versions from September 2009 on can also move a track's pitch bend over a set time. Archive mode sets the bend at once. The versions from June 2008 on can put biquad filters on a track's notes. Archive mode applies the library's preset filters. It doesn't apply a filter that a game defines in its code. Some games' AX microcode is a version that the model can't drive. Those games can only be ripped in game mode. Game mode requires a profile for the game.
- Game mode for another release of Mario Kart Wii, Wii Music or Animal Crossing: City Folk requires a profile made for it. Their version of the sound library checks a flag. The flag's address can't be found the way the functions are.
- Sounds that play until the game stops them, such as ambiences, get two loops and a fade when the ripper can find their loops. Otherwise they play until their notes end, for at most ten minutes.
- Only sequences are ripped. Use tools such as vgmstream for BRSTM streams. Wave sounds, and sequences whose data the game can't load, are skipped.
- The output is the TV's stereo mix. The Wii Remote speaker's sounds and surround aren't played.
- Effects that a game runs on its auxiliary buses, such as reverb, aren't played. The rips have the dry mix.
- Archive mode doesn't play JAudio2. `wsfrip` therefore can't rip another JAudio2 game or another release of Twilight Princess. It stops with an error that says so.
- Encrypted disc images and WADs aren't read. A WiiWare title's sound archives are read from the U8 archives among its contents. Archives inside those aren't read.
